# 🧠 Delegates & Events — One-Page Mental Guide

---

# 🔹 1. Delegate (Core Idea)

> A delegate is a **type-safe reference to one or more methods**.

### Think:

* Variable → stores values
* Delegate → stores **methods**

---

## 🔹 What a delegate knows

* ✔ Method **parameters**
* ✔ Method **return type**

👉 It does **NOT care**:

* What the method does
* When it will be called

---

## 🔹 Basic form

```csharp
public delegate void MyDelegate(int x);
```

---

## 🔹 Usage

```csharp
MyDelegate d = SomeMethod;
d(5);
```

---

# 🔹 2. Multicast Delegate

> A delegate can store **multiple methods**, not just one.

---

## 🔹 How

```csharp
d += Method1;
d += Method2;
```

---

## 🔹 What happens when invoked

```csharp
d();
```

👉 Calls:

```
Method1 → Method2 → Method3 (in order)
```

---

## 🔹 Important rules

* ✔ Executes in **order added**
* ✔ If `void` → all run normally
* ⚠ If returns value → **last result only**
* ⚠ If exception → stops execution

---

# 🔹 3. Why Delegates Exist

They allow:

* Passing **behavior as a parameter**
* Writing **flexible code**

---

## 🔹 Example mindset

```csharp
Process(data, condition, action);
```

👉 You pass:

* what to check
* what to do

---

# 🔹 4. Event (Core Idea)

> An event is a **controlled (safe) delegate used for notifications**

---

## 🔥 Key difference

| Feature        | Delegate | Event |
| -------------- | -------- | ----- |
| Assign (`=`)   | ✅        | ❌     |
| Invoke outside | ✅        | ❌     |
| Encapsulation  | ❌        | ✅     |

---

# 🔹 5. Why Events Exist

Problem with delegate:

```csharp
btn.OnClick = null;   // ❌ dangerous
btn.OnClick();        // ❌ wrong trigger
```

---

## 🔹 Event solves this

```csharp
public event Action OnClick;
```

Outside class:

```csharp
btn.OnClick += Handler; // ✅
btn.OnClick();          // ❌
btn.OnClick = null;     // ❌
```

---

# 🔹 6. Event Roles

### 1. Publisher

The class that **owns and raises the event**

### 2. Subscriber

The class that **listens and reacts**

---

# 🔹 7. Event Flow (VERY IMPORTANT)

```
1. Event declared
2. Subscribers attach (+=)
3. Action happens
4. Publisher invokes event
5. All subscribers run
```

---

# 🔹 8. Example Flow

```csharp
class Button
{
    public event Action OnClick;

    public void Click()
    {
        OnClick?.Invoke(); // 🔥 event fired
    }
}
```

---

```csharp
btn.OnClick += () => Console.WriteLine("Log");
btn.OnClick += () => Console.WriteLine("Email");

btn.Click();
```

---

# 🔹 9. Mental Model (CRITICAL)

### Delegate:

> “Here are methods I can call”

### Event:

> “Something happened—notify everyone”

# 🔹 10. Your Understanding (Refined & Locked)

Here’s your idea rewritten perfectly:

> A delegate is a type-safe reference to one or more methods, allowing methods to be passed and invoked without knowing their implementation, only their signature. When multiple methods are assigned, it becomes a multicast delegate. An event is a restricted wrapper around a delegate that enforces encapsulation by allowing external code to only subscribe or unsubscribe, while preventing direct invocation or reassignment. The publisher defines and raises the event, and subscribers react when the event is triggered.

# 🔹 11. When to Use What

### ✅ Use Delegate:

* Internal logic
* Passing behavior
* Callbacks

---

### ✅ Use Event:

* Notifications
* UI interactions
* System reactions

* Event = **safe delegate for notification**
* `+=` = subscribe
* `Invoke()` = fire event
* Only **publisher triggers**, others **listen**
