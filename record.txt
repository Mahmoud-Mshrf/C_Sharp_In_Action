🔹 1. What is a Record?

A record is a special reference type designed for representing data rather than behavior.

🔥 Main Difference from Class
Normal class

Compared by:

reference
Record

Compared by:

value (data)
🔹 Example
Class
class Person
{
    public string Name { get; set; }
}
var p1 = new Person { Name = "Mahmoud" };
var p2 = new Person { Name = "Mahmoud" };

Console.WriteLine(p1 == p2);

Result:

False ❌

Because:

different references
🔹 Record
record Person(string Name);
var p1 = new Person("Mahmoud");
var p2 = new Person("Mahmoud");

Console.WriteLine(p1 == p2);

Result:

True ✅

Because:

records compare values

Record:

record Person(string Name);

Roughly behaves like:

class Person

    public string Name { get; init; }

        Name = name;

    public override bool Equals(object obj) { ... }

🔹 2. Positional Records

Most common syntax:

record Person(string Name, int Age);
Automatically creates properties
Person p = new("Mahmoud", 22);

Console.WriteLine(p.Name);
🔹 3. Non-positional Records

You can also write them like classes:

record Person
{
    public string Name { get; init; }
    public int Age { get; init; }
}
🔥 init keyword (VERY IMPORTANT)
public string Name { get; init; }

Means:

can set only during object creation
Example
var p = new Person { Name = "Mahmoud" };

p.Name = "Mohamed"; // ❌
🔹 4. Records are Reference Types

Very important.

record ≠ value type

Default record:

reference type

Like class.

🔹 5. Record Struct

If you want value type:

record struct Point(int X, int Y);
🔥 Difference
Type	Reference/Value
record	Reference type
record struct	Value type
🔹 6. with Expression (VERY IMPORTANT)

This is one of the best record features.

Example
record Person(string Name, int Age);

var p1 = new Person("Mahmoud", 22);

var p2 = p1 with { Age = 23 };
What happens?
NEW object created
copied from old object
modified specified values
🔥 Original unchanged
p1 → Mahmoud, 22
p2 → Mahmoud, 23
🧠 This supports immutability beautifully
🔹 7. Deconstruction

Records support deconstruction automatically.

Example
var p = new Person("Mahmoud", 22);

var (name, age) = p;
🔹 8. ToString() automatically
Console.WriteLine(p);

Output:

Person { Name = Mahmoud, Age = 22 }
🔹 9. Equality in Records

Records compare:

property values
not references
🔥 Huge difference
record Person(string Name);
new Person("A") == new Person("A")

✔ True

🔴 But classes:
reference equality by default
🔹 10. Inheritance in Records

Records support inheritance.

Example

record Employee(string Name, decimal Salary)
    : Person(Name);
🔹 11. Immutability in Records

Records encourage immutability but do NOT force it.

⚡ Final Comprehensive Summary (your style)

Records are special data-oriented reference types in C# that provide built-in value equality, concise syntax, automatic generation of equality members, deconstruction, and immutability-friendly behavior. Unlike classes, records compare objects based on their data instead of memory references. They support features like positional syntax, with expressions for non-destructive mutation, and automatic ToString, making them ideal for immutable models, DTOs, and value objects. Records encourage immutability through init properties but do not enforce deep immutability automatically.
